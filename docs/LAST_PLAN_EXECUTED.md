## Contexto

Este módulo ya es dueño de `work_calendar_weekly` / `work_calendar_exception` /
`work_calendar_config` y ya tiene las ops de escritura (`upsert_weekly_calendar`,
`add_calendar_exception`, `remove_calendar_exception`) y de cálculo
(`list_availability`). Falta:

1. Exponer las **lecturas crudas** que un editor necesita (los métodos de
   `Repository` ya existen: `ListWeeklyCalendar`, `ListExceptions`).
2. Un **cliente caller-side tipado** que la app (Etapa D) adapta al componente
   `scheduleeditor` — este módulo NO puede importar `components`/`layout`
   (blacklist de renderer en `veltylabs/modules/AGENTS.md`), así que entrega
   datos + métodos, no un widget.
3. **Publicar `schedule.changed`** al mutar la agenda, para que `reservation`
   recalcule (Etapa G).

`docs/ARCHITECTURE.md §7` decía "No second view for calendar configuration… If a
future app screen needs one, it is a small, separate addition" — esto es ese
añadido. Actualizar esa sección al implementar (quitar la frase de "no view",
describir las 2 list-ops + el cliente).

### 2. Evento `schedule.changed` (`service.go`)

```go
const EventScheduleChanged = "appointment.schedule.changed"

// ScheduleChangedPayload es el payload tipado del evento. Implementa
// model.Encodable (EncodeFields + IsNil) —lo que events.Event.Payload exige— y
// también model.Decodable (DecodeFields), para que webtyp/sse pueda
// serializar/deserializar en mjosefa-cms; el broker in-proc de la demo entrega
// el puntero concreto sin codificar. Escribir a mano (es trivial) o agregar una
// model.Definition y regenerar con ormc — cualquiera; a mano es menos ruido.
type ScheduleChangedPayload struct {
    TenantId string
    StaffId  string
}
func (p *ScheduleChangedPayload) IsNil() bool { return p == nil }
func (p *ScheduleChangedPayload) EncodeFields(w model.FieldWriter) {
    w.String("tenant_id", p.TenantId)
    w.String("staff_id", p.StaffId)
}
func (p *ScheduleChangedPayload) DecodeFields(r model.FieldReader) {
    p.TenantId, _ = r.String("tenant_id")
    p.StaffId, _ = r.String("staff_id")
}
```

Publicar (fire-and-forget, guardado con `if m.pub != nil`) al final exitoso de:
- `UpsertWeeklyCalendar(cal)` → `m.pub.Publish(events.Event{Topic: EventScheduleChanged, Payload: &ScheduleChangedPayload{cal.TenantId, cal.StaffId}})`
- `AddException(exc)` → idem con `exc.TenantId, exc.StaffId`
- `RemoveException(tenantId, exceptionId)` → hace falta el `staffId`, y hoy
  **`Repository` no tiene un `GetException`** (solo `ListExceptions` por rango y
  `DeleteException`). Agregar `Repository.GetException(tenantId, id) (WorkCalendarException, error)`
  (mismo patrón que `GetReservation`: `Query(...).Where(Id).Eq(id).Where(TenantId).Eq(tenantId)`,
  `orm.ErrNotFound` → `ErrNotFound`). En `service.go`, `RemoveException` hace
  `exc, err := m.repo.GetException(tenantId, exceptionId)` antes de borrar, y
  publica con `exc.StaffId`. `Repository.DeleteException` queda igual.

`UpsertCalendarConfig` **no** publica (activar/desactivar el calendario completo
es un evento distinto; fuera de alcance).

### 3. Cliente caller-side (`schedule_client.go`, nuevo)

Contraparte tipada de las ops, para que la app la adapte a `scheduleeditor`.
Importa solo `router` + `model` (+ los tipos de este paquete).

```go
// ScheduleClient es la vista caller-side de la agenda de UN profesional.
type ScheduleClient struct {
    caller   router.Caller
    tenantId string
    staffId  string
}

func NewScheduleClient(caller router.Caller, tenantId, staffId string) *ScheduleClient

// Lecturas
func (c *ScheduleClient) Weekly(done func([]WorkCalendarWeekly, error))
func (c *ScheduleClient) Exceptions(from, to int64, done func([]WorkCalendarException, error))

// Escrituras (thin wrappers sobre las ops upsert/add/remove)
func (c *ScheduleClient) SaveWeeklyRow(row WorkCalendarWeekly, done func(error))
func (c *ScheduleClient) AddException(exc WorkCalendarException, done func(error))
func (c *ScheduleClient) RemoveException(exceptionId string, done func(error))
```

Cada método arma el `*Args` correspondiente (inyectando `tenantId`/`staffId`),
llama `c.caller.Call(op, args, into, done)` y decodifica. `done` propaga el error
del `Caller` tal cual (nunca lo traga).
