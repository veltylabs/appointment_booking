## 1. The problem

This module publishes exactly one view surface, and it can only list:

```go
// view.go — current code
// NewView construye el Presenter de Reservation — acotado al horario de un solo staff [...]
// Solo lista: sin capacidad Saver/Deleter (las reservas solo mutan vía las
// transiciones FSM-guardadas de ChangeReservationStatus, y nunca se eliminan físicamente).
func NewView(caller router.Caller, tenantId, staffId string) view.Presenter {
	return view.New(
		reservationLister{caller: caller, tenantId: tenantId, staffId: staffId},
		&Reservation{},
		view.WithTitle(titleReservations),
	)
}
```

`Reservation` is the **persisted** record. Every one of its fields is declared
with a base kind (`model.Text()`, `model.Int()`, `model.Float()`), deliberately:
it is a DB row, not a form. `webtyp.com/form`'s `New` skips any field whose
`Type` does not assert to `input.Input`:

```go
// webtyp/form/form.go — the loop that decides what gets rendered
inpKind, ok := field.Type.(input.Input)
if !ok {
	continue // skip fields with no UI binding
}
```

So a `crudview` built on `NewView`'s presenter renders an **empty form**: there
is no way to create a reservation through this module's own view surface.

Consumers work around it by declaring a *duplicate* local record with
`input.*` widgets plus a bespoke lister/saver that translates to and from this
module's ops. That workaround now exists in one application and is about to be
copied into a second — which is the signal that it was library code the first
time. Two applications will disagree about slot conversion, status mapping and
date parsing, and each will re-discover the timezone trap in §4.3 alone.

## 2. What this plan adds

A second, **form-capable** view surface beside the list-only one. The persisted
`Reservation` record is not touched.

| Symbol | File | Role |
|---|---|---|
| `ReservationFormModel` | `model.go` | `model.Definition` — the FORM projection of a reservation |
| `ReservationForm` | `model_orm.go` | generated by `ormc` from the above |
| `FormConfig` | `view.go` | the scope + injection a booking form needs |
| `NewFormView` | `view.go` | `view.Presenter` with List **and** Save |
| `FreeSlots` | `view.go` | the free slots of one day, as `"HH:MM"` local strings |
| `ErrNoServiceConfig`, `ErrIncompleteSlot` | `service.go` | new sentinels |

## 3. Design gate

1. **Prior art.**
   - *Django REST Framework* separates the model from the `ModelSerializer`/form
     that renders and validates it; the model never carries widget metadata.
   - *Rails* separates `ActiveRecord` models from `form_with`/form objects, and
     the community's "form object" pattern exists precisely for a form whose
     shape is not the table's shape.
   - *Ent* (Go) generates the persisted entity and leaves input shaping to a
     separate `Create`/`Update` builder.
   All three keep two types. We do the same, and differ in one way: our two
   types live in the same package and share one transport (`router.Caller` +
   the module's ops), so the translation between them cannot drift out of the
   module the way an app-side serializer can.
   The **rejected** alternative is putting `input.*` widgets on `Reservation`
   itself. It fails because `Reservation` is scanned from the DB by `ormc` and
   carries 22 fields — snapshots, revision, `status_before_conflict`,
   `rescheduled_from_id` — that a booking form must never render, and because
   widgets on a persisted record would make every consumer's `form.New` offer
   the audit trail as editable inputs.
2. **Novice-name test.**
   - "New form view for reservations" — `NewFormView(caller, cfg)`. It sits next
     to `NewView`, and the difference between the two names is exactly the
     difference between them.
   - "The reservation form" — `ReservationForm`. A junior would not confuse it
     with `Reservation`.
   - "Free slots for that day" — `FreeSlots(caller, cfg, day)`.
   - "Form config" — `FormConfig`. Same shape as `Deps`, which this repo
     already uses for injected collaborators.
3. **Complexity ledger.**
   - Concepts: `+1` — "a reservation has a form projection distinct from its
     row". It is the concept the duplicate app-side record was already an
     unnamed instance of.
   - Files: `+0` new files in the root package (`model.go`, `view.go`,
     `lister.go`, `service.go` all exist); `+1` test file.
   - Call-site lines: an application drops ~180 lines (a local record with
     hand-written `EncodeFields`/`DecodeFields`, a lister, a saver, two date
     helpers) and writes ~8.
   - Ways to do it: `−1` — booking a reservation from a UI had no supported
     way and one copied way. Now it has one supported way.
   - Net: negative from the second consumer onward, which already exists.
4. **Where it belongs.** Here, not in an app and not in a new package. The
   translation it performs — local `day`+`hour` → `slot_start_utc` through the
   calendar's timezone — is the same conversion `ListAvailability` performs
   internally (`service.go`, `LocalIntToUnixUTC`). Putting it anywhere else
   guarantees the two drift.
5. **What it deletes.** Nothing in this repository — this is additive. What it
   makes deletable is the duplicate record + store in every consuming app; that
   deletion happens in those repos, not here.

## 4. Stages

### Stage 1 — `ReservationFormModel` in `model.go`

Add one `model.Definition`. Place it immediately after `ReservationModel` and
above the transport-only block, with this exact field set:

```go
// ReservationFormModel is the FORM PROJECTION of a reservation: the six values a
// person actually fills in or reads when booking at a counter. It is NOT a table
// — it is never passed to migrate.Migrate, and `migrate/migrate.go` creates
// exactly five tables, none of them this one.
//
// It exists because ReservationModel's fields are base kinds (model.Text() and
// friends) on purpose: it is a DB row, and webtyp/form skips any field whose
// Type does not assert to input.Input. A form built on Reservation renders
// nothing. The two types are kept apart rather than merged so that the audit
// fields of a reservation — the snapshots, revision, status_before_conflict,
// rescheduled_from_id — can never surface as editable inputs.
//
// Widget policy is BY ROLE, the same rule the transport models below follow:
// input.X() only on what a person edits; a base kind on what is displayed and
// never typed. status is therefore model.Text(): it is shown in the list and is
// unreachable from the form, because status moves only through the FSM
// (ChangeReservationStatus).
var ReservationFormModel = model.Definition{
	Name: "reservation_form",
	Fields: model.Fields{
		{Name: "id", Type: input.Text(), NotNull: true, DB: &model.FieldDB{PK: true}},
		{Name: "client_id", Type: input.Text(), NotNull: true},
		{Name: "day", Type: input.Date(), NotNull: true},
		{Name: "hour", Type: input.Hour(), NotNull: true},
		{Name: "notes", Type: input.Textarea()},
		{Name: "status", Type: model.Text()},
	},
}
```

Two details that are decisions, not accidents:

- **`id` carries `DB: &model.FieldDB{PK: true}`** even though this is not a
  table. `form.New` hides a PK field automatically
  (`if field.IsPK() && !hasShowField(...) { continue }`) and `crudview`
  auto-assigns it on submit. Without the PK marker the form would render a text
  box asking the user to type an id.
- **`status` has no widget**, so `form.New` skips it and it still reaches the
  list through `Item()`.

Then run `ormc` to regenerate `model_orm.go`. **Never hand-edit
`model_orm.go`.** It gains `ReservationForm`, `ReservationFormList` and
`ReservationForm_`.

**Anti-footgun:** `ormc` will generate table-shaped helpers for
`ReservationForm` because of the PK marker. That is expected and harmless. Do
**not** add it to `migrate/migrate.go`, and do not "fix" the generator.

### Stage 2 — `FormConfig` and `Item()` in `view.go`

```go
// FormConfig is the scope a booking form works inside, plus the one thing this
// module cannot know: how to name a client.
type FormConfig struct {
	TenantId string // required
	StaffId  string // required — the professional whose agenda is being booked
	// ServiceConfigId is the employee_service_config the reservation points at.
	// It is what fixes duration and price; required to save or to list slots.
	ServiceConfigId string
	// Timezone is the IANA zone the day/hour pair is read in, e.g.
	// "America/Santiago". Required.
	//
	// KNOWN LIMITATION: the authoritative value lives in this module's own
	// work_calendar_config.timezone, and there is no read op for it — a caller
	// therefore supplies it. Adding get_calendar_config is deliberately out of
	// this plan's scope; until it exists, an establishment whose professionals
	// span two zones cannot be served by one FormConfig.
	Timezone string
	// From and To bound the listing, as midnight-UTC seconds.
	From, To int64
	// ActorId is recorded as creator_user_id. Optional.
	ActorId string
	// LabelFor turns a client id into the name shown in the list. Optional: nil
	// falls back to the raw id.
	//
	// It is a function, not a directory dependency, on purpose — this module
	// resolves a client through the injected DirectoryReader on the SERVER, and
	// must not acquire a second, caller-side dependency on any particular
	// directory implementation.
	LabelFor func(clientId string) string
}
```

Add `Item()` on the generated form record — in `view.go`, next to
`Reservation`'s existing `Item()`, never inside `model_orm.go`:

```go
// Item implements view.Itemizer. LeadMain is the hour because the booking list
// is read down a column of times; a list widget that leads with a time
// (webtyp/components targethour) binds to it.
func (r *ReservationForm) Item() view.Item {
	return view.Item{
		ID:          r.Id,
		LeadMain:    r.Hour,
		Label:       r.ClientId,
		Description: r.Status,
	}
}
```

`Label` is overwritten with `LabelFor(r.ClientId)` by the store in stage 3 when
the hook is set — `Item()` itself stays dependency-free.

### Stage 3 — the store, in `lister.go`

Add `reservationFormStore` beside the existing `reservationLister`. It
implements **`view.Lister` and `view.Saver`, and nothing else.**

```go
type reservationFormStore struct {
	caller router.Caller
	cfg    FormConfig
}
```

**`List() ([]model.Model, error)`**

- Return `nil, nil` when `cfg.StaffId == ""` — an unscoped booking list has
  nothing to show, and this is not an error.
- Call `OpListReservationsByStaff` with
  `&ListReservationsByStaffArgs{TenantId: cfg.TenantId, StaffId: cfg.StaffId, From: cfg.From, To: cfg.To}`
  into a `&ReservationList{}`.
- Map every row to a `*ReservationForm`:

  | `ReservationForm` | source |
  |---|---|
  | `Id` | `r.Id` |
  | `ClientId` | `r.ClientId` |
  | `Day` | `r.LocalStringDate` |
  | `Hour` | `r.LocalStringTime` |
  | `Notes` | `r.Notes` |
  | `Status` | `r.Status` — the raw FSM constant, never a translated label |

  `Status` stays the raw constant (`PENDING`, `CONFIRMED`, …). Translation to a
  human language is the consuming app's job — this module renders no hardcoded
  human language.

**`Save(recs ...model.Model) error`**

- Empty `recs` → `fmt.Err("appointment_booking: save: empty records")`.
- `cfg.ServiceConfigId == ""` → the new sentinel `ErrNoServiceConfig`.
- For each record, assert `*ReservationForm`, then compute the slot:

  ```go
  slot := LocalIntToUnixUTC(dayToUnix(r.Day), minutesOfDay(r.Hour), s.cfg.Timezone)
  ```

  `slot == 0` → `ErrIncompleteSlot`.
- Call `OpCreateReservation` with:

  ```go
  &CreateReservationArgs{
      TenantId:                s.cfg.TenantId,
      ClientId:                r.ClientId,
      CreatorUserId:           s.cfg.ActorId,
      EmployeeServiceConfigId: s.cfg.ServiceConfigId,
      SlotStartUtc:            slot,
      Notes:                   r.Notes,
  }
  ```
- Return the first call error unwrapped.

**Do NOT implement `Update` or `Delete`.** `view` re-exposes only the
capabilities the lister actually has, and `crudview` paints an edit or delete
button for each capability it finds. Implementing them to return an error would
paint two buttons that always fail. A reservation moves only through
`ChangeReservationStatus`, and is never physically deleted — the absence of
those methods is the API saying so.

Acceptance: `grep -n "func (s \*reservationFormStore)" lister.go` returns
exactly two lines, `List` and `Save`.

### Stage 4 — `NewFormView` and `FreeSlots` in `view.go`

```go
const titleBooking = "Reserva"

// NewFormView builds a presenter that both LISTS a professional's reservations
// and CREATES new ones — the surface a booking screen needs. NewView, above,
// remains the list-only surface for a read-only consumer.
func NewFormView(caller router.Caller, cfg FormConfig) view.Presenter {
	return view.New(
		reservationFormStore{caller: caller, cfg: cfg},
		&ReservationForm{},
		view.WithTitle(titleBooking),
	)
}
```

```go
// FreeSlots returns the bookable slots of one day as "HH:MM" strings in
// cfg.Timezone, ready for a list widget to render as empty rows.
//
// day is "YYYY-MM-DD". Returns nil (no error) when the scope is incomplete —
// no staff or no service config means there is nothing to compute, not a
// failure.
func FreeSlots(caller router.Caller, cfg FormConfig, day string) ([]string, error)
```

It calls `OpListAvailability` with
`&ListAvailabilityArgs{TenantId, StaffId, ConfigId: cfg.ServiceConfigId, From: dayToUnix(day), To: dayToUnix(day)}`
into a `&TimeSlotList{}`, and formats each `TimeSlot.StartUtc`.

**`ConfigId` is the `employee_service_config` id, not the
`work_calendar_config` id** — `service.go`'s `ListAvailability` resolves it with
`GetEmployeeServiceConfig(configId)`. Getting this wrong returns an empty slot
list with no error, which looks like "fully booked".

### 4.3 Date and time helpers — the trap, stated once

Add two unexported helpers in `lister.go` and use them from every call site in
stages 3 and 4. Do not inline these conversions anywhere else.

```go
// dayToUnix converts "YYYY-MM-DD" to midnight UTC in seconds — the encoding
// work_calendar_block.specific_date and the From/To op args use. 0 on failure.
func dayToUnix(day string) int64

// minutesOfDay converts "HH:MM" to minutes from midnight. -1 on failure.
func minutesOfDay(hour string) int
```

**Anti-footgun — `webtyp.com/time` ships an asymmetric pair.** `ParseDate`
returns UTC; `FormatDate` *applies the timezone offset*. They look like
inverses and are not. Round-tripping a calendar date through them shifts it by
the offset, and at any negative offset — America/Santiago is UTC−3 — that is a
whole day:

```
2026-09-08 → ParseDate → 1788825600 → FormatDate → 2026-09-07
```

A calendar date has no timezone: the 8th is the 8th everywhere. So:

- `"YYYY-MM-DD"` → seconds: **`tinytime.ParseDate`**, then `/ 1e9` (it returns
  nanoseconds).
- seconds → `"YYYY-MM-DD"`: **`tinytime.FormatISO8601(sec * 1e9)[:10]`**, which
  is documented as UTC. **Never `FormatDate`.**
- `"HH:MM"` → minutes: **`tinytime.ParseTime`**.
- A slot's UTC start → `"HH:MM"` local: **`tinytime.FormatTime(sec * 1e9)`**,
  truncated to 5 characters.

This module imports `webtyp.com/time` under the alias `tinytime`; keep it.
